# JoyOPC V0.3 — Real Product + Multimodal + Real Market Data

## Goal
V0.3 moves the product-selection loop from demo/manual inputs toward real operating data while preserving the Product Zone Method as the final business decision layer.

## Flow A — Supplier catalog to candidate pipeline

Supplier CSV/XLSX -> field normalization -> ProductCandidate -> margin calculation -> Product Zone Engine -> SCALE / TEST / HOLD / REJECT -> CEO approval -> Master Product.

Supported headers include both English and common Chinese names. See `sample_data/supplier_catalog.csv`.

## Flow B — Market data to automatic re-evaluation

Market export CSV/XLSX or webhook -> MarketSignal -> relevant-signal matching -> CandidateIntelligenceEngine -> automatic candidate re-evaluation.

The market layer influences demand and competition, but cannot bypass the Exclusive / Advantage / Homogeneous strategy rules.

## Flow C — Product assets to multimodal intelligence

Candidate -> image/PDF/text upload -> ProductAsset -> MultimodalGateway -> MultimodalAnalysis -> optional score application -> Product Zone re-evaluation.

Provider modes:

- `local-structured`: parses PDF/text and image metadata. It explicitly does NOT claim image semantic understanding.
- `openai-responses-vision`: enabled only when `OPENAI_API_KEY` is configured. Images plus extracted document context are sent through the provider gateway.

The provider can suggest changes only to bounded selection inputs (`uniqueness`, `content_advantage`, `compliance_risk`, `return_risk`). It does not directly approve products.

## Flow D — Live market connector

`GoogleTrendsAdapter` provides a best-effort live public trend signal via `pytrends`. Because this is not a stable official Google Trends API contract, the connector is isolated and failure does not block file/webhook ingestion.

## Flow E — AiSoul public-page crawler

JoyOPC ports AiSoul `page_fetcher` + `trend_crawler` discipline:

- public http(s) only, with SSRF / private-IP rejection
- fail-fast: fetch or parse failure never writes a fake `MarketSignal`
- provenance source is `crawl:<host>` and `signal_grade=inferred_external`
- crawl scores may adjust demand / competition, never bypass Exclusive / Advantage / Homogeneous rules

API: `POST /api/market/crawl` with `{ market, urls, keywords }`.

Future marketplace account connectors (Amazon/TikTok/Shopify) should map account-specific data into the same `MarketSignal` contract instead of changing the selection engine.

## API highlights

- `POST /api/imports/supplier-catalog`
- `POST /api/imports/market-signals`
- `POST /api/market-signals/webhook`
- `POST /api/market/google-trends/pull`
- `POST /api/market/crawl`
- `POST /api/candidates/{id}/assets`
- `POST /api/candidates/{id}/multimodal-analyze`
- `GET /api/candidates/{id}/intelligence`
- `GET /api/data-pipeline`

## Non-goals in V0.3

V0.3 does not pretend that marketplace credentials exist. Amazon/TikTok seller-account APIs, listing publication, live orders, advertising spend and settlement reconciliation belong in the next connector phase after credentials are available.
