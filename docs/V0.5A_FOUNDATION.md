# JoyOPC V0.5A Foundation

V0.5A is a foundation refactor, not a feature pile-on. It prepares V0.5 for:

1. OPC tenant discriminator (`company_id`) on root aggregates.
2. Alembic migration mode for production while retaining bootstrap mode for dev/tests.
3. Database-level external-order idempotency.
4. Webhook Inbox + Transactional Outbox.
5. Decimal/Numeric financial ledger for V0.5+ settlement/ad ingestion.
6. A safety hotfix that stops SKU-only legacy costs from being multiplied across every order containing that SKU.

Development/test:

```text
JOYOPC_SCHEMA_MODE=bootstrap
```

Production:

```text
JOYOPC_SCHEMA_MODE=migrate
```

Then:

```powershell
cd apps\api
alembic upgrade head
```

V0.5A only introduces the tenant column at the database boundary. Existing V0.4 ORM queries are not yet tenant-filtered. V0.5B should add `TenantContext` before multiple OPC companies are allowed in production.

APIs:

- `GET /api/v05a/status`
- `POST /api/v05a/events/inbox`
- `GET /api/v05a/events/inbox`
- `POST /api/v05a/events/outbox`
- `GET /api/v05a/events/outbox`
